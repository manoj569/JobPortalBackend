# Hiring Drives backend

Admin APIs require the existing Administrator role and use ApiResponse wrappers. GET /api/admin/hiring-drives accepts PageNumber (default 1) and PageSize (default 20, maximum 100). GET /{id}, POST, PUT /{id}, and DELETE /{id} support management. DELETE soft deletes and deactivates the drive. PUT replaces editable fields, preserving analytics and creation metadata. Admin responses include Campaign, ImpressionCount, ClickCount, Ctr, and audit fields.

Public GET /api/public/hiring-drives returns current active campaigns in DisplayOrder ascending and creation time descending. Dates use UTC ISO-8601 values ending in Z. End time is inclusive for retrieval, and must be later than the start time when saving. Both JobId and ApplyUrl may be provided; JobId takes precedence. Soft deleted internal job destinations are suppressed. Company references use the existing company name/logo. Description and all audit/analytics metadata are excluded from public cards.

POST /api/public/hiring-drives/{id}/click has no destination input. It increments ClickCount atomically and returns the server-selected destinationType plus jobId or url. Unavailable drives return 404. POST /api/public/hiring-drives/impressions accepts {"driveIds":["guid"]}; send this only when cards actually become visible. It deduplicates IDs within the batch, ignores unavailable drives, and returns 204. GET never increments impressions. Batches contain 1–50 nonempty GUIDs and the body is capped at 4096 bytes.

Analytics writes share a limit of 30 requests per minute per remote IP per application instance, using the existing ASP.NET rate limiter pattern. IPs are not persisted. Counters represent accepted events rather than unique visitors; repeated accepted requests can increase counts. Multiple instances have independent rate limits. Use existing trusted proxy configuration when deployed behind a proxy. CTR is clicks / impressions * 100, or zero with no impressions.

Title is required (200 characters). Optional limits: subtitle 300, description 10000, badge text 60, location 200, experience 100, URLs 2048. Badge types: hiring, walkIn, openings, featured (or null). Image and application URLs require HTTPS, an absolute host, no credentials, control characters, or backslashes. CompanyId and JobId must reference nondeleted records. Content is plain text; consumers must render text safely rather than use HTML injection. HTTPS validation establishes URL syntax, not employer authenticity: administrators must verify external destinations and hiring claims before activating campaigns. New campaigns default inactive.

Apply the new AddHiringDrives PostgreSQL migration through the existing deployment process before deploying the API. No seed campaigns or frontend changes are included. Existing company/job administration supplies selection options. No new external service, API key, scheduled job, or analytics identity storage is required.
