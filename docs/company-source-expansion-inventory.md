Using an authenticated Administrator session, read **all pages** of `GET /api/admin/companies` and `GET /api/admin/job-sources?PageNumber=1&PageSize=100` (continue until TotalCount exhausted; omit IsActive). Resolve names, aliases, parent ownership and canonical board identity across all companies; do not rely only on GUID-scoped uniqueness. Reuse any company/source found, including inactive sources. Do not rename/reassign ownership or create another employer to work around a duplicate.

Only after those gates, create an inactive source through `POST /api/admin/job-sources` with the existing company GUID, exact verified board URL and identifier. Example for Mastercard (replace CompanyId with the actual resolved GUID):

```json
{
  "companyId": "<existing-mastercard-company-guid>",
  "careerPageUrl": "https://mastercard.wd1.myworkdayjobs.com/CorporateCareers",
  "atsType": 5,
  "atsIdentifier": "mastercard/CorporateCareers",
  "isActive": false,
  "scanIntervalMinutes": 720
}
```

For the other four, substitute the verified board and identifier above. On repeat execution, lookup first and reuse the record; HTTP 409 `duplicate_job_source` means reread and reuse, not change the identifier. No automatic seed/startup activation was added. This is an idempotent operator workflow, not an idempotent POST contract.

Rights approval uses existing `JobAggregation:SourceApprovals:<source-id>` fields CompanyId, AtsType, AtsIdentifier, CareerPageUrl, RightsEvidence and RightsExpireAtUtc; public accessibility is not a licence. Keep IndiaOnly=true, category optional, logo rights separately reviewed and scheduler disabled. Do not invent rights evidence or arbitrary GUIDs. Any later sample import needs explicit rights and operator approval; a positive TestImportLimit marks an incomplete validation run, but it does not establish bounded upstream enumeration. Use these direct probes for bounded discovery instead. Do not enqueue `/run` as a discovery check.

After approval, an operator can update the existing record through PUT `/api/admin/job-sources/<id>` preserving exact identity and ownership. Activation, full ingestion and automatic scheduling require their own approval; this task performs none. Workday hardening dependencies and completeness/reconciliation safeguards remain with the other task.
